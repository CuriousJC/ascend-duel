# Analysis snapshots

**A skill's report, written down on the day it was run.** Everything here is *output* — the file
is a photograph of the catalogue, not a description of it, and the thing that makes it useful is
the same thing that makes it go stale.

## The rules

- **Every file is dated in its own name**, `<skill>-YYYY-MM-DD.md`, and repeats the date and the
  command in its first two lines. A snapshot you cannot date is a snapshot you cannot trust.
- **The command that produced it is in the file.** If a number here is ever in doubt, re-run it
  rather than reasoning about it — that is the whole point of the classification being derived.
- **Nothing here is a source of truth.** `data/` is the catalogue, `MECHANICS.md` is the design
  record, and a snapshot is neither. When a snapshot and the data disagree, the snapshot is old.
- **Supersede rather than update.** A new run is a new dated file; the old one stays as the record
  of what the catalogue looked like then. That is different from `docs/sheets/`, which is
  regenerated in place because a sheet is a picture of the *current* game.
- **Delete a snapshot once its findings have been acted on or rejected**, unless it is being kept
  deliberately as a before-and-after. A directory of stale photographs is a running cost.
