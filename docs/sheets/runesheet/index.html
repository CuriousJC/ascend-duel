Every card here is drawn by internal/cards, the same code the game blits, and every word beside it is read out of data/runes.json through internal/session's own validation — so a rune this page refuses to draw is a rune the game refuses to start with.

Read the sentence against the rule. The line under each name is the Text field, which is what a player reads on resting on the rune; the monospace line under it is the rule that actually fires. Nothing in the codebase checks one against the other, and this is the least readable record in data/ — which of Rider, Value and Count the rules read depends entirely on the target.

The face is a picture and a name. A rune card prints no sentence, so the line beside each one here is the tooltip’s rather than the face’s. A sheet that drew the sentence onto the card would be showing a card the game does not deal.

They are spent between the turns of a fight, never inside one. That is the thing about this catalog no card can show: the sack is gated on planning, because ResolveRound decides a whole round before playback starts and a card altered mid-playback would show a face disagreeing with a blow already computed.

The subject paragraph is the art brief, and it lives on the record. The quoted block under each rune is Draw in data/runes.json: what the thing is and what it is doing, in one sentence. Nothing in the game reads it. It is pasted under docs/art/essence_art_prompt.MD — a rune draws on the essence card's style — with its body plan from docs/art/rune_art_prompt.MD between the two. Those are the only parts of a brief that are not about one record. A rune with no subject and no art is the backlog — both lines go pink, so the page can be scrolled for what still needs writing. default-rune.png is the seat art goes into; it was the essence's own placeholder until 2026-09-12, and the two split because one shared picture is a page where a drawn essence and an undrawn rune look identical.

What the catalog does

Every target, and how many runes sit at it. The vocabulary is closed — a new target is a Go change plus one place applying it, never something a file can assert into existence — so a target with nothing under it is a mechanic built and never reached for. This was the page's grouping until families landed, and it made a poor heading once a third of the catalog was a single swap: the motif is what tells one swap from another.

Card states

The three states a rune card is drawn in — one more than an essence has. Selected is a state here and is not one there: a rune is armed first and aimed second, so the board piece has to say which one is in hand while the player picks what it eats.
