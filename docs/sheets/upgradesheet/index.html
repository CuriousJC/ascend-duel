Upgrade sheet

All 11 visible upgrades a card can carry, each drawn on all four form marks. The card is cards.Hand, 200×280; the form mark's box is 32px at (10,10); the ticks are 20×8.

A card has a form, an element and an action — and then one upgrade. A second upgrade replaces the first outright. An upgrade is drawn as a strip down each side of the face: the art data/edges.json names for it, stretched to the face's height, on the left edge and mirrored on the right, under everything written on the card. An upgrade with no record of its own draws default. Each plate prints its record's Width, Inset and Opacity, measured on the hand card; tune them in the file and re-run.

Stacked, as the deck panel stacks them

The plain card, then every upgrade in order, at half size, each drawn over the one before it — so what shows of each is its left edge. The first row is the panel's resting pitch; the second is a row that has had to tighten. This is the view the strip is for.

Each upgrade below carries the tooltip a card wearing it actually shows, built by internal/carddesc — the same call screens.cardTip makes, not a copy of it. The card is a fire Skewer and the duelist behind it hits for 10, so a figure that looks wrong can be checked by eye. There are no relics on, which is why the block is the whole panel: the game appends its damage chain only when a relic has moved something. The coloring is the game's too — the same cards.ElementSpans table the screen reads — which is why FIRE is red and CHROMATIC is not: the wheel has no hue left for "all of them".
